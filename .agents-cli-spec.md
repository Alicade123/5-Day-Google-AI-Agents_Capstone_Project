# Agent Spec — Server Health Monitoring Agent

## Overview

An AI-powered server health monitoring assistant that observes system metrics, service health, infrastructure endpoints, and logs; reasons over collected evidence; and returns structured explanations with confidence scores and remediation recommendations. Built with Google ADK for agent orchestration, FastAPI for the API layer, and a clean-architecture Python backend.

The agent never fabricates metrics. When evidence is insufficient it states: "I could not obtain sufficient evidence." All responses distinguish **Facts** vs **Possible explanations** vs **Confidence** vs **Recommended actions**.

## Example Use Cases

| Input | Expected behavior |
|-------|-------------------|
| "Why is server performance degrading?" | Gather CPU, memory, disk, logs, service health; correlate; return ranked causes with confidence |
| "Check database connectivity" | Run DB connectivity tool; report factual status and latency |
| "Summarize errors in the last hour" | Log analyzer tool; pattern summary with severity |
| "Is port 443 open?" | Port scanner tool; factual open/closed status |

## Constraints & Safety Rules

1. **Never fabricate metrics** — only report tool-returned data
2. **Insufficient evidence** — explicit message when tools fail or data missing
3. **Facts vs inferences** — always labeled in agent output
4. **Deterministic tools first** — LLM reasons over tool output, does not invent numbers
5. **No destructive actions** — recommend only; do not auto-restart services without explicit future feature flag
6. **Configurable thresholds** — anomaly detection uses config, not LLM guesses

## Success Criteria

- All monitoring tools return structured Pydantic models
- API endpoints: GET /health, /metrics, /logs; POST /agent/query, /analyze; GET /incidents
- Agent workflow: plan → execute tools → reason → structured response
- Unit tests pass for tools, services, API contracts
- Integration test covers end-to-end agent query with mocked LLM
- Structured logging with request IDs and tool execution history

## Architecture & Sub-Agents

Single root ADK agent with tool functions. Internal layers (not separate ADK sub-agents initially):

- **Planner** — intent classification + tool selection (ADK + prompt)
- **Tool Executor** — deterministic tool runner with tracing
- **Reasoning Layer** — anomaly correlation service (deterministic + LLM synthesis)
- **Memory Layer** — SQLite short/long-term store
- **Response Generator** — structured `AgentResponse` model

## Deployment Preference

Prototype first (local FastAPI + ADK). Cloud Run deployment optional in Phase 6.
